# 2026-11-26：三个真实 Agent 的本地联调记录

这次完成的是当前 v1 付款规则的完整演示。Agent 1、2、3 都调用了真实模型；没有把固定回答或手写参考合约当成 AI 生成结果。日期按纽约时间记载，原始运行目录使用 UTC，因而显示 11 月 27 日。

## PR #4 如何接入

以徐露源的 PR #4 提交 `c2e7f82c099bef4f3ddafd9345f3b9ac28ccf7f1` 为起点，在独立集成分支上继续开发，保留原提交和原有参考演示。

审查中复现并修复了三个边界问题：

1. 上一轮尚未解决的问题可能在下一轮被遗漏。例如总金额与阶段金额矛盾，用户只补钱包后，模型不再返回原问题。现在保留原问题，必须提供当前用户原文中的解决依据；总额矛盾未解决时不能自动用阶段之和覆盖它。
2. 金额证据会把 `1,500 ETH` 的尾部误当成 `500 ETH`。现在要求完整数字边界。
3. 地址证据会接受超长地址的前 40 位。现在要求完整地址边界。

上述缺陷用受控提取结果复现，不代表真实模型发生这些错误的频率。完整语义理解仍依赖模型，引用原文也不等于证明理解正确，因此保留用户确认和后续独立评测。

网页新增真实对话、待解决问题、付款摘要和独立确认页。Node 保存草稿版本和完整对话，失败请求必须显式重试；确认后的草稿封存，修改需新建。通过检查的 Agent 2 结果继续接现有部署与 Agent 3，不改合约接口或验证标准。

输入为一份合成网站开发描述：总价 0.01 测试 ETH，首页 30%，完整网站 70%；客户一次存入全部资金，按顺序验收。第一条消息提供客户测试地址，刻意省略开发者地址；没有期限、退款或自动验收要求。

| 环节 | 实际观察 |
| --- | --- |

| Agent 1 第二轮 | 补钱包后返回 `readyForConfirmation`，没有待解决问题或超范围条款 |

| 本地部署 | 在网页明确点击部署，部署的是本次通过验证的源码产物 |

Agent 1 的两个回合、用户确认和生成启动通过真实 HTTP 接口进行；部署、三个自然语言操作及交易确认通过浏览器进行。另有页面自动测试覆盖聊天、确认与失败恢复。没有把本次描述成全部从浏览器输入的手工测试。

Agent 1 使用配置的 `gpt-5.4-mini`，Agent 2 实际返回模型标识 `gpt-5.4-mini-2026-03-17`，Agent 3 操作分类使用 `gpt-5.6-luna`。Agent 3 的交易结果由确定性代码根据回执与链上状态汇报，不再次让模型猜测成功与否。

Agent 2 记录了 3 次模型调用，输入 4,842 tokens、输出 7,653 tokens，总计 12,495 tokens；生成、检查、修复总耗时 69.772 秒。这不包括 Agent 1、3 的用量和网页操作时间，也不是正式实验结果；本轮没有核算完整美元费用。
