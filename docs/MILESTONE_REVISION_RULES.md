# 多轮修改时的托管资金

2026 年 11 月 13 日产品决策。此页用于设计下一版合约。当前 v1 支持一次足额存款、按序验收和支付，后续阶段的终止退款仍待实现。

## 已确认的退出规则

双方签约时约定，Alice 或 Bob 任一方可以终止**后续尚未开工**的阶段。符合条件的阶段款退给原付款方 Alice。任一方行使这项约定好的权利时，无须再次征得另一方同意。已经完成的付款保持原结果，当前正在修改或有争议的阶段款继续托管。

网站项目预存 0.010 测试 ETH，其中首页占 0.003、整站占 0.007。下表列出成功交易后的预期金额。一次正常的提出修改意见或重新提交，本身不发生转账。

| 事件 | 合约余额 | Bob 累计实收 | Alice 累计获退 | 阶段状态 |
| --- | ---: | ---: | ---: | --- |
| Alice 足额存入，首页开始 | 0.010 | 0 | 0 | 首页进行中，整站未开工 |
| 首页经过多轮修改，双方对是否达标有异议 | 0.010 | 0 | 0 | 首页款继续托管，整站仍未开工 |
| 任一方终止未开工的整站阶段 | 0.003 | 0 | 0.007 | 整站关闭，首页争议仍待处理 |
| 举例：双方后来确认首页款中 0.002 付 Bob、0.001 退 Alice | 0 | 0.002 | 0.008 | 示例结清；该比例需要双方同意 |

资金按阶段计算。重复发出终止请求，或双方先后请求终止同一阶段，只能产生一笔退款。处于修改、验收或争议中的阶段已经开工，单方面终止后续阶段的权限不涉及这笔钱。

## 待共同确认的细节

- **开工的判定。** 建议引入可记录的“开始阶段”操作，并保持阶段顺序，这样系统可以查询第二阶段是否已开始。还要决定由谁标记、是否需要双方确认，防止有人抢先标记或在线下已经开工后被系统误判。
- **当前阶段的结算。** 建议 Alice 验收后付清该阶段；有异议时，任一方可提结算方案，另一方明确同意后执行。双方愿意继续工作时可以继续修改。若一直谈不拢且没有约定兜底条款，当前阶段的争议款可能长期留在合约。
- **每轮修改的条件。** 签约前写清包含哪些修改、提交反馈与重新交付期限，并区分原规格缺陷和新增需求。若约定沉默期满可以领取，要定义及时提出修改意见之后如何暂停、此期限从哪次提交重新计算。

实现这条退出规则时，需要同步更新规则字段、Agent 1 支持清单、Agent 2 合约接口与行为测试、Agent 3 的可选操作、签名角色及网页。验收时至少检查双方分别发起、同一阶段重复请求、当前阶段本金保留和退款后余额。
